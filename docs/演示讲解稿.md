# 演示视频讲解稿（逐段口播，照着念即可）

> 语速适中，每段对应一个镜头。括号内为操作提示，不用念。

## 开头（镜头 1：项目结构）

大家好，这是灵境竞赛组物联网方向第一阶段的考核项目——虚拟机器人设备服务。
项目分为两部分：`server` 目录是部署在 Ubuntu 虚拟机里的服务端，使用 Python 和 FastAPI 编写；`client` 目录是运行在 Windows 本地的客户端，包括命令行客户端、带轨迹可视化的图形客户端和一键演示脚本。

## 镜头 2：启动服务端

现在我们在 Ubuntu 虚拟机里启动服务端。运行一键启动脚本 `run.sh`，它会自动创建虚拟环境、安装依赖，并打印本机 IP。可以看到服务已经监听在 8000 端口。注意这里必须监听 0.0.0.0，Windows 才能通过局域网访问到它。

## 镜头 3：网络互通

回到 Windows，先 ping 一下虚拟机的 IP，确认局域网已经互通。

## 镜头 4：查询接口

接下来运行一键演示脚本，依次调用全部接口。首先看设备状态接口 `/status`：返回设备在线状态、运行状态、实时位置和电量。再看传感器接口 `/sensor`：温度、湿度、电压、障碍物距离和 IMU 数据，数值是"基准值加随机扰动"，并且和运动状态联动。

## 镜头 5：运动控制

现在向 `/move` 接口发送前进指令：方向 forward、速度 0.5 米每秒、距离 0.3 米。过一会儿再查状态，可以看到设备的 X 坐标从 0 变成了 0.3——位置是随时间真实演化的，而不是瞬间跳变。

## 镜头 6：预设任务

接下来提交预设任务 square。服务端会把它规划成"四段直行加四次九十度转弯"。我们轮询状态观察轨迹：位置沿正方形四个顶点依次移动，朝向从 0 度转到 90、180、270 度，最后回到起点附近，任务完成后设备自动回到 idle 空闲状态。

## 镜头 7：停止中断

再提交一个持续巡逻任务 patrol，设备会一直巡逻。在它运行过程中调用 `/stop`，可以看到设备立即停止，进入 stopped 状态——这是考核点"任务执行中可以中断"。
另外演示两个健壮性处理：发送非法参数（速度为负）时，服务端返回 422 校验错误而不是崩溃；设备忙的时候再下发运动指令，会返回 409 冲突提示。

## 镜头 8：图形客户端

最后看一下图形客户端。左侧是控制按钮，右侧画布每 400 毫秒轮询一次状态，实时画出机器人的位置、朝向和行进轨迹。执行一个正方形任务，可以看到轨迹在画布上实时勾勒出来。点击停止，设备立即停下。

## 结尾

以上就是全部演示：服务端具备状态保存与更新能力，状态会持久化到 JSON 文件，重启服务后位置和电量都能恢复；Windows 客户端完成了全部接口的调用。谢谢观看。
